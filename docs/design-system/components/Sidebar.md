# Sidebar

shadcn's Sidebar laid out as in Figma's `Sidebar` symbol: 256px on the page colour (`sidebar`) with a `sidebar-border` hairline at its right, 12px side padding, 16px between blocks.

- **Window row** (inside a `WorkspaceShell`, docked and in the drawer; Figma's `SidebarWindowRow`, a `platform` variant per platform): 48px, the title bar's start at the left (the traffic lights on macOS, the menu button on Windows, nothing on Linux: see `WindowBar`), then the sidebar toggle beside it, and back and forward at the right (28px muted icon buttons, 8px apart). It starts exactly as the `WindowBar` does (16px in, the same gaps), so the toggle stands in the same place whether the sidebar is docked, in the drawer or hidden.
- **Header:** a 20px `WorkspaceTile`, the workspace name (14px medium `foreground`) and a 12px up-down chevron that opens the `WorkspaceSwitcher` (the row fills with `sidebar-accent` on hover and `accent` while open); then search and new (`SidebarAction`: 28px icon buttons with their shortcut in the tooltip).
- **Items:** every item, in the main navigation and in Recents and Favorites, is the same: 32px, 8px in, 16px icon (or an event's 16px `ColourBar`), 14px `sidebar-foreground` label, 8px corners. Hover fills `sidebar-accent`; the current page takes `sidebar-accent` with a `border-strong` outline drawn inside (so labels never shift). The main navigation's items are 2px apart; Recents and Favorites stack edge to edge under Nova's 32px label (12px medium at 70%), which folds the group away when clicked (its chevron shows on hover); groups fold by default, `collapsible={false}` keeps one open.
- **Footer:** the `SyncStatus` line, then Trash, Settings and Help, pushed to the bottom.
- **Scrolling:** in a window too short for every item, the window row and the workspace switcher row (with search and new) stay put, and everything below them, the footer included, scrolls as one beneath them. It scrolls in a `ScrollArea`, whose thin scrollbar shows over the right edge (taking no width from the items), and while anything is scrolled under them they cast `shadow-pinned`. The two rows are one pinned block: the page passes its switcher row as the sidebar's `header` (`<Sidebar header={<SidebarHeader>…</SidebarHeader>}>`), and the sidebar draws it under its own window row, so neither row needs to know the other's height.

The sidebar has one layout. Inside a `WorkspaceShell` it is **docked** at the left or **hidden** (the user's choice, ⌘\, at any size; and always in compact windows, below `breakpoint-medium`), and while hidden it opens as a **drawer** over the page: pointing at the sidebar toggle or the window's left edge peeks at it, and clicking the toggle pins it open (or docks it, where the window is wide enough). `WorkspaceShell` does all of this, and the motion (see its guide); the sidebar only renders. In the drawer it carries `data-drawer`, its window row doesn't drag the window, and picking an item closes the drawer.

**Base UI:** No single Base UI part: shadcn's Sidebar layout built from plain markup, with Base UI `Menu` for the workspace switcher and `Collapsible` for collapsible groups. Active items carry `data-active`.

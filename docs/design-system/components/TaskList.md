# TaskList

A virtualized list of `TaskRow`s that handles selection: rows selected next to each other join into one block, every row shows its checkbox while anything is selected, and the `SelectionBar` floats over the bottom of the list.

- **Data.** `tasks` (core's `TaskListItem`s as they are, `TaskRowData[]`) for a flat list, or `groups` for the grouped view: each `{ id, heading, tasks, collapsed?, footer? }`, where `heading` is a `GroupHeading` (and anything drawn under it, such as an event's `EventRow`) and `footer` a "Show more" row while the group has more to load.
- **Virtualized** with `@tanstack/react-virtual`: only the rows in view, and about ten either side, are in the DOM, so 5,000 tasks draw about 30 rows. The list sits inside the page or sheet that scrolls it and virtualizes against that scroller (its nearest scrolling ancestor, or the window), offset by where the list starts in it. Rows are sized from the `row-height` token (48px), read from the page so a denser setting follows; headings start at `group-height` plus `group-gap` and are measured as they draw.
- **Grouped view.** Headings and rows are one flat list. The heading of the group at the top of the view sticks to the top (on `--list-ground`, the page's `background` by default; set it on a card or sheet), with `group-gap` above every heading but the first. Collapsing a group (`collapsed`) leaves its rows out of the list.
- **Loading more.** `onEndReached` fires once the last drawn row comes within `endReachedThreshold` (20) rows of the end, once for each length of the list: call `fetchNextPage()` there.
- **Focus and selection are kept as task ids**, never as DOM focus alone, so they survive a row scrolling out of view and unmounting. `selected` / `defaultSelected` / `onSelectedChange` take the selected tasks' `id`s (`string[]`); `focusedId` / `onFocusedIdChange` the focused row's (the first row by default). Moving focus to a row off screen calls `scrollToIndex` first, then focuses it once it is drawn. The list is one tab stop: the focused row, or the list itself while that row is scrolled away, which brings it back.
- **Accessibility.** `role="grid"` with `aria-rowcount` (`rowCount`, the total a count gives, or the loaded rows and headings) and `aria-rowindex` on every drawn row and heading, so a screen reader announces "row 212 of 340" with 30 rows in the DOM. Browser find (⌘F) sees only drawn rows; ⌘K searches everything.
- **Pictures.** `states` (`{taskIndex: 'hover' | 'focus'}`), `menuOpenAt` (a row with its status menu open), `subtasks` (indent every row), `selectionBar: false` to leave the bar to the page.
- Keyboard: ↑/↓ move between rows (scrolling the next into view), Home/End to the first and last loaded row, `X` selects, `S` opens the status menu, Enter opens the task.
- Stories: `1,000 rows` (loaded 100 at a time from `onEndReached`), `1,000 rows, grouped` (sticky headings) and `In scrolling panel`.

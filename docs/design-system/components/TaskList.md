# TaskList

A virtualized list of `TaskRow`s that handles selection: rows selected next to each other join into one block, every row shows its checkbox while anything is selected, and the `SelectionBar` floats over the bottom of the list.

- **Data.** `tasks` (core's `TaskListItem`s as they are, `TaskRowData[]`) for a flat list, or `groups` for the grouped view: each `{ id, heading, tasks, collapsed?, footer? }`, where `heading` is a `GroupHeading` (and anything drawn under it, such as an event's `EventRow`) and `footer` a "Show more" row while the group has more to load.
- **Its own scroller.** The list fills the height its container gives it (`flex: 1` in a column: placed straight in a `PageContent layout="list"`, or a set height) and scrolls its rows there, under the page header, which never scrolls away. Virtualized with `react-virtuoso` against itself (`Virtuoso` for `tasks`, `GroupedVirtuoso` for `groups`): only the rows in view, and about ten rows' height either side (`increaseViewportBy`), are in the DOM, so 5,000 tasks draw about 30 rows. Virtuoso measures every row as it draws; until then a row counts as `row-height` (48px, `defaultItemHeight`, read from the generated `src/renderer/styles/tokens.ts`).
- **Short lists.** With no height to fill it grows to its rows and draws them all, which suits a short list (a task's subtasks). Virtuoso's viewport is positioned, so a scroller left to size itself would collapse to nothing: the list's height is set to Virtuoso's total (`--list-height`, from `totalListHeightChanged`), and `flex: 1 1 auto; min-height: 0; max-height: 100%` shrink that to whatever room a flex column or a set height gives. In development, a list drawing 200 rows or more that way logs a warning naming it, as it was meant to scroll.
- **Grouped view.** Headings and rows are one list. The current group's heading is stuck to the top in Virtuoso's top item list, which replaces the heading's place in the list rather than copying it, so the heading is in the DOM once and ahead of its rows; the next heading covers it as it arrives. It sits on `--list-ground` (the page's `background` by default; set it on a card or sheet). The `group-gap` between groups is the last item of every group but the last (no role, `aria-hidden`), not padding on the next heading: Virtuoso sticks a heading when the top of its box reaches the top of the list, so a gap inside the box would make it jump. Collapsing a group (`collapsed`) leaves its rows out of the list.
- **Loading more.** `onEndReached` fires once the last drawn row comes within `endReachedThreshold` (20) rows of the end, once for each length of the list (from Virtuoso's `rangeChanged`): call `fetchNextPage()` there.
- **Focus and selection are kept as task ids**, never as DOM focus alone, so they survive a row scrolling out of view and unmounting. `selected` / `defaultSelected` / `onSelectedChange` take the selected tasks' `id`s (`string[]`); `focusedId` / `onFocusedIdChange` the focused row's (the first row by default). Moving focus to a row off screen calls Virtuoso's `scrollIntoView` first (which scrolls only as far as it takes, and keeps the row out from under the stuck heading), then focuses it once it is drawn. The list is one tab stop: the focused row, or the list itself while that row is scrolled away, which brings it back.
- **Accessibility.** `role="grid"` with `aria-rowcount` (`rowCount`, the total a count gives, or the loaded rows and headings) and `aria-rowindex` on every drawn row and heading (Virtuoso's `Item` is the `TaskRow` itself, its `Group` the heading's row, with no wrapper), so a screen reader announces "row 212 of 340" with 30 rows in the DOM. Browser find (⌘F) sees only drawn rows; ⌘K searches everything.
- **Pictures.** `states` (`{taskIndex: 'hover' | 'focus'}`), `menuOpenAt` (a row with its status menu open), `subtasks` (indent every row), `selectionBar: false` to leave the bar to the page.
- Keyboard: ↑/↓ move between rows (scrolling the next into view), Home/End to the first and last loaded row, `X` selects, `S` opens the status menu, Enter opens the task.
- Stories: `1,000 rows` (loaded 100 at a time from `onEndReached`) and `1,000 rows, grouped` (sticky headings), each filling a page's content area under its header.

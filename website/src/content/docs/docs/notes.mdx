Notes are for everything you write: specs, meeting notes, decisions, checklists. You write in rich
text, and DevBrain saves each note as a Markdown file in your workspace, in
[GitHub Flavored Markdown](https://github.github.com/gfm/).

## Writing a note

Press <kbd>N</kbd> anywhere, choose **New note** in the title bar's **+** menu, or type a title in
[Home](/docs/home/#quick-capture)'s capture box with **Note** picked. The note opens with the cursor
in its title; press <kbd>Enter</kbd> to move into the body.

There's no save button: a note saves as you type, and when you leave it or switch to another app.

## The Notes page

Show notes as a **List** (with a one-line preview) or as **Cards**, from **Display** in the
toolbar.

- **Sort by** in **Display**: **Last edited** (the default), **Created** or **Title**.
- **Filter** by what the note is **Linked to** (an event, a task or nothing), or by **Project**.
- Right-click a note to open it, favourite it, change its link or project, copy it as Markdown or
  move it to the trash.

## Linking notes

A note can be:

- **In a project**: **+ Add to project** under its title, or **Change project** in its **…** menu.
- **The note of one event or one task**: **Link to** in its **…** menu. A meeting's note is the
  usual case: start one from the event in the [calendar](/docs/calendar/#meeting-notes), and it
  opens beside the event while the meeting happens.

The links show as pills under the title. Click one to open the project, task or event.

### Tasks from a note

Any number of tasks can point back at a note, such as the follow-ups from a meeting. To make one:

- **+ Add task**, under the title, creates a **New task linked to this note**, or links an existing
  one.
- **<kbd>/</kbd>task**, typed in the text, opens **New task** linked to the note and in its project.
  Type it at the end of a line, such as `Send Ana the proration rules /task`, and the line becomes
  the task's title. Only the `/task` is removed: the line stays as you wrote it.
- **Turn into task**, in the [format toolbar](#formatting-text), creates a task from the text you
  selected, linked to the note and in its project, and puts a link to the task in place of the text.

Once a note has tasks, the pill says how many and how they're going ("3 tasks · 2 in progress").
Click it for the list: change a task's status from its icon, click a task to open it beside the
note, or right-click it for its menu. **Link** links an existing task, and **New** creates one.

### Mentions

Type <kbd>@</kbd> in any note, then a few words, to link a task, another note or an event right in
the text. The link shows the item's current title, and clicking it opens the item. The note or
item you're writing in isn't offered: nothing mentions itself. Mentions work the
same way in the descriptions of tasks, projects and events.

### Mentioned in

Every task, note, project and event shows what mentions it, so you can find your way back to the
notes and tasks that talk about it.

- **On a page**, a pill says how many: **4 mentions** under a note's title, on a task's links line,
  or after a project's dates. Click it for the list.
- **In a sheet** (a task's, a note's or an event's), **Mentioned in** is at the end, folded to one
  line. Click it to open it.

Each item in the list shows what it is (a note, a task with its status, a project, an event) and
when it last changed, most recent first. Click one to open it. A meeting's note shows with a
calendar icon. Items in the trash aren't listed, and nothing shows while nothing mentions the item.

Tasks and events from Linear and Google Calendar can be mentioned, but their descriptions are the
provider's, so links in them aren't counted.

## The editor

The same editor is used everywhere you write in DevBrain: notes, and the descriptions of tasks,
projects and events.

### GitHub Flavored Markdown

What you write is stored as [GitHub Flavored Markdown](https://github.github.com/gfm/) (GFM), the
Markdown of READMEs, issues and pull requests. A note reads the same on GitHub as in DevBrain, and
you can paste one into an issue, or a README into a note, without losing its formatting.

- **GFM covers** headings, bold, italic, strikethrough, inline code, bulleted, numbered and to-do
  lists, quotes, code blocks, tables, links and dividers. Callouts are GitHub's alerts
  (`> [!NOTE]`).
- **For what GFM has no syntax for**, DevBrain writes the HTML tags GitHub reads: `<u>` for
  underline, `<kbd>` for a key, `<sub>` and `<sup>`, and `<details>` for a collapsible section.
- **Links to tasks, notes and events** are ordinary Markdown links to a `devbrain://` address, such
  as `[Proration rules](devbrain://note/nte_…)`, so in another app they read as plain links.

You never have to write Markdown yourself: the menus, shortcuts and toolbar produce it, and Markdown
you do type turns into formatting as you type.

### Blocks

Type <kbd>/</kbd> at the start of a line for the block menu, or type the Markdown shortcut:

| Block                  | Shortcut                       |
| ---------------------- | ------------------------------ |
| Heading 1, 2, 3        | `#`, `##`, `###` and a space   |
| Bulleted list          | `-` and a space                |
| Numbered list          | `1.` and a space               |
| To-do list (checklist) | `[ ]` and a space              |
| Quote                  | `>` and a space                |
| Code block             | ` ``` `                        |
| Divider                | `---`                          |
| Callout                | <kbd>/</kbd> menu: **Callout** |
| Table                  | <kbd>/</kbd> menu: **Table**   |
| Collapsible section    | <kbd>/</kbd> menu              |

- **Code blocks** highlight about 35 languages. Click the label above a block to choose its
  language; a block with none stays plain text.
- **Callouts** are GitHub's alerts: Note, Tip, Important, Warning or Caution. Click the callout's
  title to change its kind.
- **To-do items** are checkboxes in the note, saved as `- [ ]` and `- [x]`. They aren't DevBrain
  tasks; use **+ Add task** for those.
- The block menu's **DevBrain** section links a note, a task or an event, like <kbd>@</kbd>. Its
  **Task** opens **New task** (see [Tasks from a note](#tasks-from-a-note)); in a project's or task's
  description, the task goes in that project.

### Tables

**Table** in the block menu opens a size grid beside it: point at a size and click, or press

<kbd>→</kbd> and choose one with the arrow keys and <kbd>Enter</kbd>. <kbd>Enter</kbd> on **Table**
itself gives you three columns by three rows.

While you work in a table:

- **Point at a column or a row** for a handle on its edge. Click the handle for the column's or
  row's menu: align a column left, center or right, sort it, insert, move, duplicate, clear or
  delete. Drag the handle to move the column or row.
- **Point at the line between two columns or rows**, just outside the table, for a **+** that
  inserts one there. The bars under and beside the table add a row or a column at the end.
- **The bar above the table** turns the header row on or off, shows the table's size, copies it as
  Markdown and deletes it.
- **Drag across cells** to select them, then align their columns, clear them or delete their rows
  or columns. <kbd>Backspace</kbd> clears them.

In a cell, <kbd>Enter</kbd> goes to the cell below, adding a row at the end, and <kbd>⇧ Enter</kbd>
starts a new line in the cell. Deleting a row, a column or the table shows **Undo**.

A table is saved as a Markdown table, so it offers what one can hold: a header row, an alignment
for each column, and text with formatting and line breaks in each cell. There are no merged cells,
colours or column widths.

### Formatting text

Select text for the format toolbar: **Turn into** another block, **Bold** (<kbd>⌘B</kbd>),
**Italic** (<kbd>⌘I</kbd>), **Underline** (<kbd>⌘U</kbd>), **Strikethrough** (<kbd>⌘⇧X</kbd>),
**Code** (<kbd>⌘E</kbd>), **Link** (<kbd>⌘K</kbd>) and **Turn into task**. Markdown typed inline
works too: `**bold**`, `*italic*`, `~~strike~~` and `` `code` ``.

**Turn into task** creates a task titled with the selected text, with your default priority and due
date, and replaces the text with a link to it. In a note, the task is linked to the note and in its
project; in a project's or task's description, it's in that project. It's there when the selection
is within one paragraph, heading or list item, outside a code block.

To open a link in your browser, <kbd>⌘</kbd>-click it (<kbd>Ctrl</kbd>-click on Windows and
Linux).

### Copying and pasting

- Copying puts Markdown on the clipboard, so a note pastes cleanly into a pull request, an issue or
  a chat.
- Pasting Markdown, from a README or an issue, turns it into formatting. Pasting from a web page or
  a document keeps its formatting. <kbd>⌘⇧V</kbd> (<kbd>Ctrl Shift V</kbd>) pastes plain text.
- Code copied from VS Code becomes a code block in its language.

### What the editor doesn't show

For your safety, a note never loads anything from the internet:

- **Images** show as a chip with their description; click it to open the image in your browser,
  or the link when the image is inside one.
- Only web (`http` and `https`) links can be opened.
- HTML that isn't one of the elements above shows as its source text.

All of these are kept in the file as you wrote them.

## How notes are stored

Each note is a Markdown file in the `notes` folder of your [workspace's folder](/docs/workspaces/),
named after the note's ID (such as `nte_….md`), with its title in front matter:

```markdown
---
id: nte_01JD3…
title: Proration rules
---

How a plan change mid-cycle is charged…
```

The note's project, links and favourite are kept in the workspace's database, not in the file.

- Opening a note never changes its file. When you edit one, DevBrain rewrites only the blocks you
  edited (a paragraph, a list, a table) and leaves the rest of the file as it was. An edited block
  keeps the way it was written: `*` bullets stay `*`, `__bold__` stays `__bold__`. What you add is
  written in DevBrain's own Markdown style (`-` for bullets, `**` for bold), and an edited table is
  lined up in columns.
- Saves are written to a new file and then moved into place, so a crash never leaves half a note.
- **Show in Finder** (Explorer, File Manager) in a note's **…** menu shows its file in your file manager.

:::caution[Editing note files outside DevBrain]
DevBrain doesn't watch the files for changes. If you edit a note's file in another app, quit
DevBrain first: while the note is open in DevBrain, its next save replaces your edit, and DevBrain
may keep showing the old text until it reopens. Keep the front matter's `id` and `title`, or
DevBrain can't read the note.
:::

To take notes out of DevBrain as Markdown named by their titles, or to bring Markdown files in, use
[Import and export](/docs/import-export/#notes).
